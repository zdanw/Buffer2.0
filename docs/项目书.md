## 1. 项目概述

### 1.1 一句话定义

**Bebcare AI Studio** 是一套面向婴儿产品品牌的全自动社交媒体内容生产与发布系统：根据产品资产与可配置的提示词维度，自动生成英文社媒文案与产品图，经去重与人工审核后，通过 Buffer 一键发布到 Instagram、Facebook、TikTok 等多平台。

### 1.2 要解决的问题

| 痛点 | 传统方式 | 本系统方案 |
|------|----------|------------|
| 多平台内容产能不足 | 人工撰写、设计，周期长 | LLM + 图像模型流水线批量产出 |
| 风格不统一、易重复 | 依赖个人经验 | 多维提示词引擎 + 图文去重 |
| 排期与发布分散 | 各平台后台手动操作 | 定时任务 + Buffer 统一发布 |
| 资产与生成割裂 | 素材库与生成工具分离 | 产品资产、维度、任务、草稿一体化 |

### 1.3 目标用户

- **运营 / 市场人员**：配置任务、审核待发内容、查看发布日历
- **内容策划**：管理提示词维度、产品卖点与品牌语气
- **管理员**：用户权限、图像 Provider / 模型配置

## 2. 建设目标与成功标准

### 2.1 建设目标

1. **内容自动化**：按 Cron 调度完成「选品 → 组 Prompt → 文案/出图 → 去重 → 草稿/直发」全链路。
2. **可控生成**：提示词维度（场景、光线、构图、风格等）可配置，并支持产品类型兼容策略。
3. **人机协同**：支持全自动发布与「生成草稿 → 人工挑选 → 发布」两种模式。
4. **多平台触达**：对接 Buffer GraphQL，覆盖主流社媒账号。
5. **可部署、可维护**：本地开发（SQLite）与生产（Supabase Postgres + HF Space）分离；CI 保障质量与部署副本同步。

### 2.2 可验证成功标准

- [ ] 配置产品与参考图后，可手动触发生成文案与图片，并上传 CDN
- [ ] 启用定时任务后，按 Cron 产出执行记录或待发草稿
- [ ] 待发草稿可挑选图文并成功推送到 Buffer 目标平台
- [ ] JWT 鉴权生效；非管理员无法访问用户/Provider 管理
- [ ] 生产环境健康检查 `/health` 通过；CORS 仅允许配置白名单

## 3. 系统架构

### 3.1 总体架构

```
┌─────────────────┐         HTTPS/JWT          ┌──────────────────────────────┐
│  Frontend       │ ◄─────────────────────────► │  Backend (FastAPI)            │
│  React + Vite   │                             │  /v1/* 业务 API               │
│  (Vercel)       │                             │  APScheduler 定时任务         │
└─────────────────┘                             └──────────────┬───────────────┘
                                                               │
        ┌──────────────────┬───────────────────┬───────────────┼───────────────┐
        ▼                  ▼                   ▼               ▼               ▼
   DeepSeek/百炼        豆包/多 Provider      Buffer API     GitHub 图床     Chroma
   (文案/图像Prompt)    (图像生成)            (社媒发布)     (CDN URL)       (向量/元数据)
        │                  │
        └──────────────────┴──────────────────► Supabase Postgres / SQLite
```

### 3.2 仓库与部署拓扑

| 目录 | 职责 |
|------|------|
| `backend/` | **开发主源码**（API、模型、迁移、测试） |
| `frontend/` | 管理后台（React 19 + TypeScript + Tailwind） |
| `hf-space/` | Hugging Face Space 部署副本（由脚本从 backend 同步） |
| `space4/` | 魔搭等部署副本（同上） |
| `scripts/sync_deploy_copies.py` | 同步 / `--check` 漂移门禁 |
| 根目录 `Dockerfile` + `README.md` | HF Space Docker SDK 入口 |

**原则**：业务改动只改 `backend/`，再执行同步后部署；CI 对漂移做 `--check`。

### 3.3 内容生成流水线（核心）

```
产品资产 + 提示词维度
        │
        ▼
  PromptEngine（平台风格 / 叙事视角 / 写作风格 / 负向提示）
        │
        ├─► DeepSeek：英文社媒文案 + 中文图像提示词
        │
        └─► 图像 Provider（豆包等）+ 参考图
                │
                ▼
        去重（pHash / MinHash；可选 CLIP）
                │
                ▼
        GitHub 图床持久化 CDN URL
                │
        ┌───────┴───────┐
        ▼               ▼
   mode=auto         mode=manual
   Buffer 直发       ManualTaskDraft 待审
```

### 5.2 后端 API（前缀 `/v1`）

| 路由组 | 能力摘要 |
|--------|----------|
| `/auth` | 登录、刷新 Token、当前用户、用户 CRUD |
| `/products` | 产品与分类、图片上传/列表/删除 |

### 5.3 核心子系统说明

#### （1）Prompt 引擎（`prompt_builder`）

- 内置平台风格：Instagram / TikTok / Facebook 等语气、长度、emoji 比例
- 叙事视角：科技测评师、忙碌妈妈、生活美学等
- 写作风格：种草、理性分析、温情故事等
- 硬性负向提示（水印、文字、商标变形等）与软性多样性建议
- 维度数据可库表管理，并按产品类型做兼容策略

#### （2）内容生成器（`generator`）

- DeepSeek Chat Completions（支持百炼 OpenAI 兼容 base URL 自动补全）
- 图像提示词系统角色面向婴儿产品商业摄影场景
- 异步生成 + 重试退避；同步封装供调度线程调用
- 生成图经工具层落盘到 GitHub CDN

#### （3）去重引擎（`dedup`）

- **pHash**：汉明距离阈值，防近似重复图
- **MinHash/LSH**：文案近重复检测
- **CLIP（可选）**：`ENABLE_CLIP=true` 时启用图向量相似度（需额外依赖）

#### （4）调度服务（`scheduler`）

- Cron 触发；同任务不重叠（`max_instances` + `coalesce`）
- 全局并发信号量，适配 HF Space 资源（可配小并发）
- 支持 `auto` / `manual` 模式与执行轨迹落库

#### （5）发布器（`publisher`）

- Buffer GraphQL 客户端，带重试
- 平台元数据映射：Instagram、Facebook、TikTok、X、LinkedIn、Pinterest、YouTube、Threads、Mastodon 等

#### （6）知识库 / 嵌入（`knowledge_base`）

- Chroma 存储图像元数据与向量检索入口
- Embedding / CLIP 后端可插拔，默认关闭重模型以降低部署成本

## 6. 数据模型（概要）

| 实体 | 说明 |
|------|------|
| `User` | 账号、密码哈希、是否管理员 |
| `Product` / `ProductImage` | 产品信息与参考图（CDN、pHash、类型） |
| `PromptDimension` 及相关 | 维度定义、产品类型、兼容策略、产品维度关联 |
| `ScheduledTask` | Cron、目标范围、平台、出图/文案数、模式、Provider |
| `TaskExecution` | 每次调度执行轨迹（状态、文案、维度、参考图、错误） |
| `ManualTaskDraft` | 人工审核草稿（多图多文、选中项、发布状态） |
| `GenerateTask` | 异步生成任务状态 |
| `ImageProvider` | 可配置图像服务商与密钥（加密存储） |
| `Publish*` / `Log` | 发布记录与系统日志 |

数据库通过 Alembic 版本迁移；启动可选 `AUTO_MIGRATE`。

## 7. 安全与合规要点

1. **鉴权**：除探活与部分 Provider 路由策略外，业务 API 依赖当前活跃用户 JWT。
2. **CORS**：`ALLOWED_ORIGINS` 显式白名单；禁止 `*` 与 credentials 组合。
3. **密钥**：`SECRET_KEY` 同时用于 JWT 与 Provider API Key 加密；生产密钥仅放 Space Secrets / 环境变量，不入库。
4. **生产库**：禁止生产使用 SQLite；应使用 Supabase Postgres（注意 Session 模式连接池参数）。
5. **日志**：对 `/health`、生成状态轮询等路径降噪，减少公网扫描与轮询刷屏。

## 8. 部署与运维

### 8.1 本地开发

```text
backend/   → 配置 .env（可参考 .env.example）→ uvicorn / 测试
frontend/  → npm ci && npm run dev（默认连 localhost API）
```

### 8.2 生产推荐拓扑

| 组件 | 建议 |
|------|------|
| 后端 | Hugging Face Space（Docker，端口 7860） |
| 前端 | Vercel，域名写入 `ALLOWED_ORIGINS` |
| 数据库 | Supabase Postgres，`APP_ENV=production` |
| 密钥 | Space Settings → Secrets（见 `hf-space/.env.example`） |

同步部署副本：

```bash
python scripts/sync_deploy_copies.py          # 同步
python scripts/sync_deploy_copies.py --check  # CI 漂移检查
```

### 8.3 CI（GitHub Actions）

- 后端：`pytest`（API + unit）
- 前端：`npm run build`（含 TypeScript）
- 部署副本：`sync_deploy_copies.py --check`

### 8.4 关键环境变量清单（摘要）

`APP_ENV`、`DATABASE_URL`、`DEEPSEEK_*`、`DOUBAO_*`、`BUFFER_*`、`GITHUB_*`、`SECRET_KEY`、`ADMIN_PASSWORD`、`ALLOWED_ORIGINS`，以及调度/连接池相关可选参数。

## 11. 风险与约束

| 风险 | 说明 | 缓解 |
|------|------|------|
| 第三方 API 配额/稳定性 | DeepSeek、豆包、Buffer 限流或变更 | 重试退避、可切换 Provider、监控失败执行 |
| HF Space 休眠与资源 | 冷启动、CPU/内存有限 | 保守并发配置、`coalesce` 合并 misfire |
| 图床与版权 | GitHub 公开仓库可见性 | 仓库权限与内容审核流程 |
| 生成内容合规 | 婴儿产品广告合规、平台审核 | 负向提示、人工审核模式、品牌语气字段 |
| 副本漂移 | hf-space 与 backend 不一致 | 同步脚本 + CI `--check` |
