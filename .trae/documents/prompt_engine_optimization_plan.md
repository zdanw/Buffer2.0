# 提示词引擎优化计划

## 一、需求分析

### 参考文件分析
参考文件 `prompt_templates.json` 提供了以下核心功能：
1. **产品类型分类**：按产品类型组织模板配置
2. **维度化配置**：场景、视角、构图、风格、画质、道具、光照
3. **示例提示词**：提供高质量参考示例
4. **冲突规则**：避免不兼容的选项组合
5. **负面提示词**：定义禁止出现的元素
6. **文案生成模板**：支持社交媒体文案生成

### 当前项目现状
当前 `prompt_engine.py` 存在以下不足：
1. 配置硬编码，缺乏灵活性
2. 缺少维度化选项配置
3. 输出为中文，需改为英文
4. 结构相对简单，扩展性不足

### 用户反馈要点
1. **不需要产品类型模板**：让模型根据产品信息自行选择合适的维度风格
2. **冲突规则由模型自行判断**：通过提示词指令引导

### 优化目标
1. 构建灵活的提示词引擎架构
2. 支持英文输出（图像提示词和文案）
3. **提供统一的维度选项，由模型自行选择**（用户反馈）
4. **冲突规则由模型自行判断**（用户反馈）
5. 增强负面提示词系统
6. 适配Bebcare母婴品牌特性

## 二、优化方案

### 2.1 架构设计

```
prompt_engine.py
├── PromptEngine (主类)
│   ├── __init__() - 加载配置
│   ├── build_copywriting_prompt() - 生成文案提示词
│   ├── build_image_prompt() - 生成图像提示词
│   └── build_negative_prompt() - 生成负面提示词
├── DIMENSIONS (统一维度配置)
│   ├── scenes - 场景选项
│   ├── viewpoints - 视角选项
│   ├── compositions - 构图选项
│   ├── styles - 风格选项
│   ├── quality - 画质选项
│   ├── details - 道具选项
│   └── lighting - 光照选项
├── NEGATIVE_PROMPT - 负面提示词规则
└── 辅助方法
    └── _render_template() - 模板渲染
```

### 2.2 核心改进点

| 改进项 | 原实现 | 优化后 |
|--------|--------|--------|
| 配置方式 | 硬编码 | 统一维度配置 |
| 输出语言 | 中文 | 英文 |
| 产品模板 | 无 | **移除产品类型模板**（用户反馈） |
| 维度配置 | 简单场景 | 7维配置（场景/视角/构图/风格/画质/道具/光照） |
| 维度选择 | 代码随机选择 | **由模型自行选择**（用户反馈） |
| 冲突处理 | 无 | **由模型自行判断**（用户反馈） |
| 负面提示词 | 简单列表 | 分层规则（硬性规则/建议规则） |

### 2.3 文件修改

**修改文件**：`backend/bebcare/prompt_builder/prompt_engine.py`

**核心变更**：
1. **移除产品类型模板概念**，提供统一的维度选项池
2. 添加7维维度配置（场景、视角、构图、风格、画质、道具、光照）
3. **由模型根据产品信息自行选择维度组合**
4. **通过提示词指令让模型处理冲突**
5. 输出全部改为英文
6. 增强负面提示词系统

## 四、核心设计原则

### 4.1 维度选择策略（由模型自行决定）

提示词指令示例：
```
Based on the product information provided, please select appropriate options from the following dimensions to create a high-quality image prompt:
- Scene options: {scenes}
- Viewpoint options: {viewpoints}
- Composition options: {compositions}
- Style options: {styles}
- Quality options: {quality}
- Detail options: {details}
- Lighting options: {lighting}

When options appear contradictory, modify appropriately to ensure realism.
```

### 4.2 优势分析

| 优势 | 说明 |
|------|------|
| 灵活性 | 模型可根据产品特性自由选择最合适的组合 |
| 智能性 | 利用模型的理解能力做出最优决策 |
| 简洁性 | 无需维护复杂的产品-维度映射关系 |
| 扩展性 | 新增产品类型无需修改配置 |

## 五、风险与注意事项

1. **模型依赖**：维度选择和冲突处理依赖模型能力，需确保提示词指令清晰
2. **英文输出质量**：需确保英文文案自然流畅，符合母婴品牌调性
3. **向后兼容**：修改需保持原有API接口不变
